# PROBLEM STATEMENT — SECONDSELF (PERSONAL AI SECOND BRAIN)

**Document Version:** 1.0  
**Status:** Approved Specification  
**System Name:** SecondSelf — Personal AI Second Brain & Karpathy-Pattern LLM Wiki  
**Context:** Local Document/Notes System + Karpathy-Pattern LLM Wiki

---

## 1. Executive Summary & Context

Every existing note-taking app and personal knowledge management (PKM) tool fails for the exact same reason: **information capture is high-friction or low-retrieval, and knowledge decays rather than compounding.**

Users capture hundreds of notes, web bookmarks, PDFs, and strategic ideas across browser tabs, mobile apps, and local files. Over time:
1. Information goes into folders nobody re-reads.
2. Bookmarks pile up unread.
3. Personal documentation (mission plans, skills profiles, project trackers) decays because maintenance requires manual hand-editing.
4. Consumed articles and videos leave no durable, queryable trace.

**SecondSelf** solves this by establishing a unified, local-first **Personal AI Second Brain**. It combines a friction-free raw capture channel with an automated AI agent maintenance loop (using the PARA framework and local vector embeddings) to organize, link, visualize, and answer natural language questions over the user's accumulated knowledge base.

---

## 2. Core Problem Statements

### 2.1 The General Knowledge Decay Problem
* **Manual Filing Breakdown:** Manual tagging and organization never happen consistently. Unorganized notes become a cluttered digital graveyard.
* **Non-Compounding Knowledge:** Reading an article in March does not automatically inform a technical build in October. Knowledge resets with every new source instead of synthesizing.
* **Information Fragmentation:** Critical notes are scattered across local folders, browser bookmarks, mobile note apps, and Google Drive without a single unified ingestion point.

### 2.2 Document Freshness & Maintenance Problem
* **Manual Maintenance Bottleneck:** Strategic personal documents (e.g., Mission Plans, Project Statuses) remain accurate only when manually edited. When project statuses or learnings evolve, living documents quickly fall out of sync with reality.

---

## 3. High-Level System Goal & Vision

> **"Not a notes app. Not a chatbot. A brain that organizes itself and answers for you."**

Build an end-to-end system where a user can capture **anything** (a plain text note, a web URL link, or a local document/file), have AI automatically classify and file it (via PARA framework), auto-link related concepts using vector embeddings, render the knowledge as a live interactive graph, synthesize natural-language answers via Retrieval-Augmented Generation (RAG), and deploy the application to a public URL.

---

## 4. Phase-by-Phase Problem & Milestone Breakdown

The system addresses the overall problem through 4 self-contained weekly milestone problems:

```
[Capture Note/Link/File] 
         │
         ▼
[Week 1 — The Archivist]  ──► One-command ingestion into raw/ with timestamp & UUID
         │
         ▼
[Week 2 — The Librarian]  ──► Auto-classify (PARA + tags + summary) & Auto-link (embeddings)
         │
         ▼
[Week 3 — The Cartographer] ─► Nodes-and-edges graph model & Interactive vis-network visualization
         │
         ▼
[Week 4 — The Oracle]    ──► Ask-your-brain RAG Q&A + Streamlit UI + Public Cloud Deployment
```

### Week 1 — The Archivist: "Capture Everything, Lose Nothing"
* **Problem:** Ideas, links, and notes are scattered across apps, browser tabs, and memory with no single landing place.
* **Goal:** Build a robust, single-command capture pipeline that takes text, links, or files and stores them into an immutable `raw/` folder with ISO timestamps and unique IDs.

### Week 2 — The Librarian: "Teach AI to Organize For You"
* **Problem:** Raw captures accumulate into an unorganized pile. Manual tagging fails, and hidden connections between related notes are lost.
* **Goal:** Implement an automated LLM classifier (Groq / Llama 3) to categorize items using PARA (*Projects, Areas, Resources, Archives*), extract tags/summaries, and compute local embeddings (`all-MiniLM-L6-v2`) to auto-link related notes without manual effort.

### Week 3 — The Cartographer: "Visualize the Brain"
* **Problem:** Organised and linked knowledge remains invisible and abstract; users cannot see how concepts connect or explore topological clusters.
* **Goal:** Transform the linked markdown wiki into a structured JSON graph model (nodes & edges) and render an interactive, force-directed graph UI (via `vis-network`) supporting drag, zoom, and hover popups.

### Week 4 — The Oracle: "Ask It Anything, Ship It Public"
* **Problem:** A visual graph is informative, but the ultimate value comes from precise, synthesized answers to complex questions grounded exclusively in personal notes.
* **Goal:** Implement a RAG Q&A engine (`ask()`), integrate it alongside the graph view into a unified Streamlit UI (`app.py`), and deploy the full pipeline to a public cloud platform (Streamlit Community Cloud / Hugging Face Spaces).

---

## 5. Scope Definition

### In-Scope (MVP & V1 Build)
* **Storage Architecture:** Immutable `raw/` storage layer + AI-maintained `wiki/` Markdown vault structured by PARA.
* **Multi-Source Capture:** Plain text notes, web URLs, YouTube video links, local files (PDFs, Markdown, Images).
* **AI Pipelines:**
  * Auto-classification into PARA folders using Groq Llama 3.
  * Local embedding generation (`sentence-transformers/all-MiniLM-L6-v2`) and cosine similarity auto-linking.
  * Natural language Q&A synthesizing answers strictly from retrieved note contexts.
* **Visualization & UI:**
  * Force-directed interactive network graph (`vis-network`).
  * Unified Streamlit web application with search bar, citation panel, graph view, and capture forms.
* **Deployment:** Git-versioned repository deployed live to Streamlit Cloud.

### Explicitly Out-of-Scope (Near-Term)
* Building a note-taking app from scratch.
* Mobile applications (native iOS/Android).
* Audio transcription pipelines beyond native YouTube transcript fetching.
* Custom database servers or multi-user access control.
* Fine-tuning custom LLM models.

## 6. Assumptions & Constraints

| ID | Category | Description |
|---|---|---|
| **A1** | Infrastructure | Groq API is available for free/fast LLM generation (Llama-3.1-8b-instant). |
| **A2** | Hardware / Performance | Local embeddings run lightweight models (`all-MiniLM-L6-v2`, ~80MB) directly on host CPU/RAM (8GB+ RAM friendly). |
| **A3** | Operating Model | Wiki pages are written and maintained by AI scripts; raw sources remain immutable. |
| **C1** | Data Privacy | Personal private documents are kept isolated or evaluated locally before sending to cloud LLMs. |
| **C2** | Cost & Tooling | Zero external software cost requirement (Free APIs, open-source libraries, free tier cloud deployment). |

---

## 7. Stakeholders & Success Criteria

### Stakeholders
* **Primary User & Operator:** Personal Second Brain Owner.
* **Downstream AI Consumers:** Automated Agents / Conductor Orchestrator requesting knowledge lookup via MCP tools.

### Measurable Success Criteria
1. **Frictionless Capture:** Single command or web form saves any text, URL, or file in under 2 seconds.
2. **Ingestion Quality:** 100% of raw captures are automatically assigned a PARA category, tags, and summary without manual intervention.
3. **Graph Connectivity:** Every wiki note maintains $\ge 2$ cross-links or auto-generated connections when similarity exceeds threshold ($0.75$).
4. **Answer Grounding:** RAG Q&A synthesizes answers exclusively from stored notes and provides clear source citations.
5. **Deployment Verification:** Full pipeline (Capture $\rightarrow$ Classify $\rightarrow$ Link $\rightarrow$ Graph $\rightarrow$ Ask $\rightarrow$ Deploy) operates end-to-end on a public URL.
