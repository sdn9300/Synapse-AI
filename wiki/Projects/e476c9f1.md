# SYSTEM ARCHITECTURE PLAN — SECONDSELF

**Document Version:** 1.0  
**Status:** Approved Technical Architecture  
**System Name:** SecondSelf Personal AI Second Brain  
**Tech Stack:** Python 3.10+, Streamlit, Groq API (Llama 3.1 8B Instant), Sentence-Transformers (`all-MiniLM-L6-v2`), Vis-Network HTML5, NumPy, PyPDF, BeautifulSoup4

---

## 1. Architectural Overview & Design Principles

SecondSelf is architected around three foundational design principles:

1. **Wiki-First, Vector-Search-Second:**  
   Unlike traditional RAG systems that query raw, noisy chunks at runtime, SecondSelf uses an AI processing loop to transform raw captures into structured, curated Markdown wiki pages (`wiki/`). Vector embeddings are computed over clean wiki notes rather than raw dumps, producing higher-signal search results and lower latency.
2. **Immutable Raw Storage vs. AI-Maintained Vault:**  
   Raw inputs (`raw/`) land as immutable records (never edited by agents). The AI maintenance pipeline reads raw captures, extracts structured YAML frontmatter and body text, and writes organized notes into the `wiki/` directory.
3. **Provider Abstraction Layer:**  
   Generation (LLM) and Embedding operations are decoupled via abstract interfaces (`GenerationProvider`, `EmbeddingProvider`). Generation defaults to Groq API (`llama-3.1-8b-instant`) with fallback to local Ollama. Embeddings are kept permanently local (`all-MiniLM-L6-v2`) to ensure fast, low-RAM (8GB-friendly) vector operations.

## 4. Data Models & Schemas

### 4.1 Dataclasses (`lib/models.py`)

```python
from dataclasses import dataclass, field
from typing import List, Optional, Dict, Any

@dataclass
class CaptureMeta:
    id: str                      # Format: YYYY-MM-DD_{uuid8}
    timestamp: str               # ISO 8601 string
    type: str                    # "note" | "link" | "file"
    source: str                  # Original URL, filepath, or "stdin"
    original_filename: Optional[str] = None
    content_hash: str = ""       # SHA-256 string for deduplication

@dataclass
class CaptureResult:
    id: str
    path: str
    type: str

@dataclass
class WikiNote:
    id: str                      # Note unique identifier
    raw_id: str                  # Corresponding raw capture ID
    para: str                    # "Projects" | "Areas" | "Resources" | "Archives"
    tags: List[str]              # Extracted keywords/tags
    summary: str                 # One-line AI summary
    created: str                 # ISO timestamp
    links: List[str] = field(default_factory=list)  # List of target note IDs
    body: str = ""               # Clean markdown body content

@dataclass
class GraphNode:
    id: str
    label: str                   # Node title/summary
    para: str                    # PARA group
    tags: List[str]
    summary: str
    content_preview: str         # First 200 characters
    group: str                   # Same as para (for vis-network coloring)

@dataclass
class GraphEdge:
    source: str
    target: str
    weight: float                # Cosine similarity score
    type: str = "related"        # Edge relationship type

@dataclass
class AskResult:
    answer: str
    sources: List[Dict[str, Any]] # List of [{id, summary, relevance_score, para}]
```

## 5. Core Subsystem & Component Specifications

### 5.1 Capture Subsystem (`capture.py` & `lib/storage.py`)
* **ID Generation:** `{YYYY-MM-DD}_{uuid4()[:8]}`.
* **Storage Logic:**
  * Creates `raw/{capture_id}/`.
  * Writes `meta.json` containing metadata and SHA-256 hash.
  * Writes raw content to `content.md`, `content.txt`, or preserves original binary extension (`content.pdf`).

### 5.2 Processing & Classification Subsystem (`classify.py` & `lib/llm.py`)
* **Text Extraction:**
  * Plain text / markdown: direct read.
  * Web links: HTTP GET using `requests` + text extraction via `BeautifulSoup4` (stripping nav/ads). Fallback to raw URL string on failure.
  * PDF files: Text extraction via `pypdf.PdfReader`. Fallback to filename on failure.
* **LLM Classification:**
  * Provider: Groq API (`llama-3.1-8b-instant`).
  * System Prompt: Instructs LLM to return strictly valid JSON matching:
    `{"para": "Projects|Areas|Resources|Archives", "tags": ["tag1", "tag2"], "summary": "One-line summary"}`.
  * Wiki Output: Saves file to `wiki/{para}/{id}.md` with YAML frontmatter header.

### 5.3 Vector Indexing & Auto-Linking Subsystem (`link.py` & `lib/embeddings.py`)
* **Vector Model:** `sentence-transformers/all-MiniLM-L6-v2` (384-dimensional output).
* **Auto-Linking Algorithm:**
  1. Load existing vectors from `data/embeddings.pkl`.
  2. For each new or updated wiki note, compute vector for text = `title + summary + body`.
  3. Calculate Cosine Similarity $S(a, b) = \frac{a \cdot b}{\|a\| \|b\|}$ against all existing note vectors.
  4. If $S(a, b) \ge 0.75$:
     * Add target ID to frontmatter `links: []`.
     * Append inline wikilink `[[target-id]]` to the note body.
  5. Save updated vectors back to `data/embeddings.pkl`.

### 5.4 Graph Visualization Subsystem (`build_graph.py` & `static/graph.html`)
* **Graph Builder:** Parses all `wiki/**/*.md` files, extracts nodes and frontmatter/inline wikilinks, deduplicates edges with normalized key `(min(id1, id2), max(id1, id2))`, and exports `data/graph.json`.
* **Frontend Rendering:**
  * Library: `vis-network` (v9.1+ CDN).
  * Physics Engine: Barnes-Hut algorithm with configuration:
    `gravitationalConstant: -8000`, `centralGravity: 0.3`, `springLength: 150`, `springConstant: 0.04`.
  * Node Styling: Distinct colors per PARA group (Projects: `#4CAF50`, Areas: `#2196F3`, Resources: `#FF9800`, Archives: `#9E9E9E`).

### 5.5 RAG Q&A Engine (`ask.py`)
* **Retrieval Workflow:**
  1. Embed user query string using `lib/embeddings.py`.
  2. Perform cosine similarity ranking over all cached vectors in `data/embeddings.pkl`.
  3. Select Top-$K$ (default $K=5$) most relevant wiki notes.
  4. Truncate context to max ~6000 tokens.
* **Synthesis & Guardrails:**
  * Temperature: `0.3`.
  * Prompt Constraint: "Answer strictly based on the provided notes. If the answer cannot be synthesized from the notes, respond: 'I don't have notes about that.'"
  * Citations: Format source references as `[note-id]`.

### 5.6 Streamlit Application UI (`app.py`)
* **Layout Structure:**
  * **Header:** Title, status metrics, and `[Refresh Graph]` action button.
  * **Ask Panel:** Search input box + `[Ask]` button $\rightarrow$ renders synthesized answer with interactive citation expandable cards.
  * **Graph Panel:** Rendered via `st.components.v1.html(open('static/graph.html').read(), height=550)`.
  * **Sidebar:** Single-command capture form (Note / Link / File upload), `[Process Pipeline]` action button, and vault statistics.
* **Performance Caching:**
  * `@st.cache_resource` for loading embedding models (`SentenceTransformer`) and Groq API client.
  * `@st.cache_data` for reading `data/graph.json` and index state.

## 7. Security, Privacy & Deployment Strategy

1. **Local-First Privacy:** All raw source content and wiki pages reside locally in private git-managed directories. Embedding models run 100% locally.
2. **Secrets Management:** `GROQ_API_KEY` is loaded exclusively from `.env` or Streamlit Cloud Secrets (`st.secrets`). `.env` and `data/embeddings.pkl` are strictly excluded via `.gitignore`.
3. **Deployment Target:** Streamlit Community Cloud (connected directly to public/private GitHub repository).
